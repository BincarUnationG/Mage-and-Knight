# 兼容性

## 版本要求

### 运行时

| 项 | 要求 | 说明 |
|---|---|---|
| Minecraft | **1.20.1** | `fabric.mod.json` 声明 `~1.20.1`，不兼容其他小版本 |
| Fabric Loader | **≥ 0.20.1** | — |
| Fabric API | 必需 | 用了 `HudRenderCallback`、`ServerPlayNetworking`、`CommandRegistrationCallback`、`ServerPlayerEvents` |
| Java | **≥ 17** | 由 `fabric.mod.json` 声明 |

### 构建时

| 项 | 要求 | 说明 |
|---|---|---|
| JDK | **21** | Fabric Loom 要求构建 JVM 为 21；版本由 `gradle/gradle-daemon-jvm.properties` 锁定（`toolchainVersion=21`） |
| Fabric Loom | 1.17.21 | **不能升到 1.18+**，那一代要求构建 JVM 为 Java 25 |
| Gradle | 9.8.2 | 走腾讯云镜像 |

> 运行时只要 Java 17+，但**构建**必须 Java 21——这两件事经常被混为一谈。若以后换到 JDK 25，可把 Loom 升到 1.19.x 并改回官方支持矩阵。

## 客户端 / 服务端

`fabric.mod.json` 里 `environment = "*"`，两边都能装：

| 环境 | 是否必需 | 说明 |
|---|---|---|
| 客户端 | **必需** | 能量条 HUD 在客户端渲染 |
| 服务端 | **必需** | 玩家数据、数值改动的校验都在服务端；自定义通道 `mage-and-knight:profile_sync` 两边都要注册 |

**只装一边不行**：缺服务端时没有数据来源，缺客户端时收不到同步包（数据不显示）。

## GUI 缩放

**全部兼容**。所有 HUD 坐标与尺寸都是 scaled 单位，随 GUI 缩放等比放大，1x ~ 4x 以及"自动"模式下比例一致、像素清晰（贴图 1:1 绘制，不缩放）。

极端情况：GUI 缩放开得很大时 `scaledWidth` 会变小（例如 1920 宽 + 缩放 4 → `scaledWidth = 480`），此时 81px 的条相对屏幕占比变大，但仍与血条对齐，不会越界。

## 与原版 HUD 的关系

| 原版元素 | 交互 |
|---|---|
| 血条 | 条紧贴其上方，不重叠 |
| 盔甲图标 | 在条下方，不遮挡 |
| 气泡（水下） | 在条下方，不遮挡 |
| 饱食度 | 在条下方，不遮挡 |
| 吸收心（金苹果） | 原版会把上面那排顶高，本条**按同样公式跟着上移**，不遮挡 |
| 血量上限提升（其他模组的加血 buff） | 同上，按 `maxHealth` 实时计算排数，自动让位 |
| 聊天框 | 位置必然落在聊天框纵向范围内，但绘制层抬到 `z = +75`，**压住聊天框底色**、不遮聊天文字 |
| F1 隐藏 HUD | 条一起隐藏 |
| 创造模式物品栏 / 打开界面 | 正常显示 |

位置公式是从原版 `InGameHud.renderStatusBars` 里抄的（`heartRows` / `rowSpacing` / 盔甲行偏移），所以原版改血量排数的行为都能跟上。

## 与第三方模组的兼容性

**没有针对任何第三方模组做过测试。** 以下是根据实现推断的风险面：

| 风险类型 | 说明 | 可能的影响 |
|---|---|---|
| 其他 HUD 模组占用同一区域 | 同样画在"血条上方"的模组（护甲显示、状态栏扩展等）会与本条重叠 | 视觉重叠，无功能冲突 |
| 修改聊天框位置 / 宽度的模组 | 本条的 z 顺序处理依赖聊天框画在 `z = 50` | 极端情况下遮挡关系反转 |
| 修改状态栏排布的模组 | 位置公式假设原版的 39 / 10 常量 | 条可能压到原版元素 |
| 其他修改玩家 NBT 的模组 | 本条用独立的嵌套标签 `mk_profile`，键名都带 `mk_` 前缀 | 冲突概率低 |
| 其他登录时发自定义包给客户端的模组 | 通道 `mage-and-knight:profile_sync` 是独立命名空间 | 无冲突 |

## 存档兼容性

- 数据存在玩家 NBT 的嵌套复合标签 `mk_profile` 里，键名统一 `mk_` 前缀
- 有数据版本号 `mk_ver`（当前 `DATA_VERSION = 2`），为将来结构变更预留升级判断
- **卸载模组后**：`mk_profile` 会作为未知标签留在存档里，重新装上后数据仍在
- **降级模组版本**：缺少的字段走安全默认值；位阶缺键默认 9（最低阶），不会意外变成 0 阶
- **不同职业的存档互切**：`/tier class` 来回切不丢位阶与经验

## 已测试环境

| 项 | 结果 |
|---|---|
| 开发客户端 + 开发服务端（`runClient` / `runServer`） | 通过，启动日志自检三项全 OK |
| 单人游戏（创建世界勾选允许作弊） | 通过，指令与 HUD 全部可用 |
| 专用服务器 | 模组能加载，HUD 在客户端正常（未做多人压力测试） |
| 开发客户端登录报 401 | 正常现象（离线开发账号），不影响测试 |
