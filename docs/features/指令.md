# 指令

目前只有一组指令：`/tier`，用于查看与调试玩家数据。所有指令都不带命名空间（直接 `/tier`），单人游戏需在创建世界时勾选「允许作弊」。

## 权限

| 指令 | 权限 | 说明 |
|---|---|---|
| `/tier` | 无 | 查看自己 |
| `/tier set <0~9>` | OP 2 | 设位阶 |
| `/tier class <mage\|knight\|none>` | OP 2 | 设职业 |
| `/tier exp add <n>` | OP 2 | 加经验（`n` ≥ 1） |
| `/tier energy set <n>` | OP 2 | 设当前能量（`n` ≥ 0） |
| `/tier sync` | OP 2 | 手动重发一次同步包 |

**为什么权限判断不写在 `.requires()` 里**

Brigadier 的 `.requires(source -> source.hasPermissionLevel(2))` 在权限不足时会让**整条分支从指令树里消失**——玩家输入 `/tier` 后补全列表里看不到 `set` / `class`，输全了也只会得到"未知指令"，完全不知道是权限问题。

现在权限判断写在每个子命令的 handler 里（`TierCommand.requirePermission`），失败会返回一句能看懂的话：

```
这个子命令需要 2 级权限（OP）。单人游戏请在创建世界时勾选「允许作弊」，或在「对局域网开放」里允许作弊。
```

## `/tier`

查看自己的完整状态。两行输出：

```
职业 魔法师 │ 位阶 4 │ 传说 │ 经验 1200
能量 200 / 280 │ 灵感 3 │ 槽位 1 / 4
```

无职业时只有一句提示，不显示位阶 / 能量：

```
你尚未踏入位阶——目前只是个普通人。
```

## `/tier set <value>`

设位阶，范围 `0~9`（`0` 最高）。设完会：

1. 把位阶写进 `PlayerProfile`
2. **把当前能量夹回新上限**（降阶时上限变小，不夹会出现"能量比上限还多"）
3. 同步给客户端
4. 回复 `位阶已设为 4 阶。`

## `/tier class <mage|knight|none>`

设职业。`none` 是退回普通人（不是"未设置"，是一个正式状态）：

- 无位阶、无能量上限、HUD 不显示
- 保留原有位阶字段的值（不主动清零，方便调试来回切）

回复 `职业已设为 魔法师。`

## `/tier exp add <amount>`

加经验（只增不减，`amount` 必须 ≥ 1）。

回复 `获得 100 点经验（累计 1200）。`

> 经验目前只是存着，还没有"攒够就升阶"的逻辑——那属于第三批。

## `/tier energy set <value>`

直接设当前能量，之后按上限夹紧（不会超过当前位阶的上限）。

回复 `能量已设为 200。`

## `/tier sync`

把服务端数据重新推一份给客户端。HUD 不刷新时用（正常流程里，任何改动数值的操作结束后都会自动同步）。

回复 `已把数据同步到客户端。`

## 最小验证流程

```
/tier                        → 普通人提示
/tier class mage             → HUD 出现空蓝条
/tier set 4                  → 上限变 280
/tier energy set 200         → 条填到约 71%
/tier energy set 20          → 条很短，开始闪烁
/tier class knight           → 条变橙、徽记变盾
/tier set 0                  → 神话阶，液体变金
/tier class none             → 条消失
```
